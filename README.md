# http-route-catalog

本地路由目录编译工具：在服务启动前编译并校验路由目录、发现冲突，并用
同一份目录完成请求路径匹配与反向链接生成，保证诊断与实际分派一致。
仅使用 Go 标准库，不启动 HTTP 服务。

## 运行

```sh
go run ./cmd/routes
```

程序从 stdin 逐行读取 JSON 请求，每个请求向 stdout 输出一行 JSON 响应。

## 协议

- `{"op":"load","routes":[{"name":"user","method":"get","path":"/u/{name}"}]}`
  编译并加载完整目录。任何校验问题都会使加载失败并保留当前目录，
  响应中 `problems` 按路由名称稳定排序，包含全部问题（路由名、行号、原因）。
- `{"op":"check","routes":[...]}` 只校验不替换；`{"op":"check"}` 报告当前目录。
- `{"op":"match","method":"GET","path":"/u/a%20b?x=1"}` 匹配请求。
  成功返回 `{"ok":true,"route":"user","values":{"name":["a b"]}}`；
  失败时 `reason` 区分 `bad_request`（含可定位 `error`）、`not_found` 与
  `method_not_allowed`（`methods` 为排序去重后的可用方法，不自动替换方法）。
- `{"op":"link","name":"user","params":{"name":["a b"]},"query":{"q":["1","2"]}}`
  反向生成链接，返回 `{"ok":true,"url":"/u/a%20b?q=1&q=2"}`。

## 路由模板语法

- 以 `/` 开头，区分大小写；方法统一按大写处理。
- 普通片段原样匹配；`{name}` 为单段参数；`*name` 为末尾多段参数，
  可匹配零段或多段。参数名只允许字母、数字、下划线且非空。
- 拒绝：空方法、空或重复路由名、同路由内重名参数、连续斜杠、`%`、`\`、
  查询串、片段标识（`#`）、`.`/`..` 片段、不在末尾的多段参数。
- 同一方法下忽略参数名后结构相同的模板互相冲突，编译失败并报告双方
  名称与位置。模板末尾斜杠（根路径除外）被忽略。

## 请求路径格式

- 必须以 `/` 开头；先剥离 `?` 后的查询部分，再按 `/` 分段并分别解码一次。
- 拒绝：连续斜杠、非法百分号编码、无效 UTF-8、解码后出现路径分隔符
  （`/`、`\`）以及 `.`/`..` 片段。请求末尾斜杠（根路径除外）被忽略。

## 匹配优先级

先收集完整匹配的候选，再按首次不同片段比较：普通片段 > 单段参数 >
多段参数；完整结束优于空多段捕获。结果与加载顺序无关。

## 反向链接

- 按路由名称读取参数：单段参数取唯一非空值；多段参数取允许为空的有序
  列表，列表项不能为空。缺少或多余参数、未知路由、值中的分隔符与
  `.`/`..` 均被拒绝。
- 各片段分别百分号编码后拼接；查询条件独立编码、按名称排序，同名多值
  保留顺序。
- 生成的路径会用该路由方法再次匹配，必须回到原路由与相同提取值，
  否则明确拒绝，绝不返回被高优先级路由截获的链接。
